API Documentation

This documentation outlines the public API endpoints for the Notification Microservice. These endpoints are designed for inter-service communication and do not require authentication.

Send Direct SMS

POST /api/v1/send/direct

Sends a direct SMS to a specified phone number. Ideal for transactional messages like order confirmations or one-time passcodes.

Request Body (JSON)

{
    "phoneNumber": "09171234567",
    "message": "Your verification code is 123456."
}

Responses

  • 200 OK: If the message is successfully sent.
  • 400 Bad Request: If `phoneNumber` or `message` is missing or empty.

Get User Preferences by User ID

GET /api/preferences/user/{userId}

Retrieves a user's alert type preferences using their internal user ID. This allows other services to know which notifications a user is subscribed to.

Responses

  • 200 OK: Returns a JSON object with the user's details and a list of their alert preferences.
  • 404 Not Found: If the user ID does not exist in the database.

Example Response Body (JSON)

{
    "userId": 1,
    "email": "user@example.com",
    "alertTypes": [
        {
            "alertId": 1,
            "alertName": "Weather Alert",
            "alertDescription": "Receive notifications about severe weather...",
            "enabled": true
        },
        {
            "alertId": 2,
            "alertName": "Emergency Alert",
            "alertDescription": "Critical emergency notifications...",
            "enabled": false
        }
    ]
}

Update User Preferences

POST /api/preferences/{email}

Updates a user's alert preferences based on their email. This endpoint completely replaces the user's existing preferences with the ones provided in the request.

Request Body (JSON)

{
    "alertTypes": [
        { "alertId": 1, "enabled": true },
        { "alertId": 2, "enabled": false },
        { "alertId": 3, "enabled": true }
    ]
}

Responses

  • 200 OK: If preferences are updated successfully.
  • 404 Not Found: If no user is found with the provided email.

Get All Alert Types

GET /api/v1/alert-types

Retrieves a list of all available alert types. This is useful for front-end applications that need to display subscription options to users.

Responses

  • 200 OK: Returns a JSON array of alert type objects.

Send Notification to Specific User

POST /api/v1/send/user/{userId}

Sends an SMS to a single user identified by their user ID. This is a generic endpoint for sending messages that are not tied to a specific alert type.

Request Body (JSON)

{
    "content": "Your package has been shipped and will arrive tomorrow."
}

Responses

  • 200 OK: If the message is successfully sent.
  • 400 Bad Request: If `content` is missing, or if the user is not found or has no phone number.

Broadcast to All Users

POST /api/v1/send/all

Broadcasts a generic SMS to every user in the database who has a registered phone number. This should be used with caution.

Request Body (JSON)

{
    "content": "System-wide announcement: The service will be down for maintenance tonight at 2 AM."
}

Responses

  • 200 OK: Returns a confirmation with a count of users the message was sent to.
  • 400 Bad Request: If `content` is missing.
